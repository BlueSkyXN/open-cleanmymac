## 3. 下一位开发者的最小交付说明

每次只围绕用户批准的任务给出：

1. 目标：哪条用户流程、识别对象或调用契约需要改进。
2. 现状：已有源码、测试、经验和真实缺口；别把缺少 pack 当缺少功能。
3. 范围：保留/修改/不做项；是否触及公共参数、schema、持久化或动作范围。
4. 证据：来源与版本、正反输入、失败行为；未经核实的假设单列。
5. 验收：正常、异常、取消/阻断、计量与执行后检查；本地与 CI 分开。
6. 停止条件：批准范围已满足后结束；新对象/新风险/不确定权限回到用户决定。

文档结构不是需要新增框架的理由。可以只改一个 scanner、一条说明或一个测试；
不要求每次产生 Observation、Strategy、Run Store 和研究命令整套产物。
